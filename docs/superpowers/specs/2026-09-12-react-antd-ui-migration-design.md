# React and Ant Design UI Migration Design

## Problem

The active editor UI is rendered by imperative DOM code. This makes its panels, forms, validation states, history controls, and account controls inconsistent with a component library and difficult to compose.

## Solution

Replace the active browser UI with a React application styled and composed with Ant Design. Preserve the existing waveform document as the sole semantic source of truth. Existing domain operations, validation, import/export, SVG generation, browser-local history, and Google-session worker remain authoritative.

## User stories

1. As a signed-in user, I want to reach the React editor after the existing Google sign-in flow, so that account protection remains unchanged.
2. As a waveform author, I want Ant Design controls for creating and editing signals, transitions, timings, phases, annotations, and metadata, so that all existing authoring tasks remain available in a coherent UI.
3. As a waveform author, I want to retain direct SVG interaction for transitions, markers, timing/phase lanes, endpoints, slot width, and canvas pan, so that precise waveform editing remains unchanged.
4. As a waveform author, I want document history, the built-in example, import, repair mode, JSON view, PNG export, and JSON export to retain their prior behavior, so that no existing work is lost.
5. As a user with an invalid import or invalid authoring state, I want clear Ant Design validation and repair feedback, so that I can correct the document without rendering an unsafe projection.

## Architecture

- `src/domain/**` and `src/render/**` remain framework-independent and are not rewritten.
- A React root owns UI state: current document, validation result, editor/repair mode, history, selected transition, current view, relation-creation state, drag feedback, and notification state.
- React components render all application panels and use Ant Design `Layout`, `Card`, `Collapse`, `Form`, `Input`, `Select`, `Button`, `Alert`, `Tabs`, `Drawer`, `Upload`, `Modal`, `message`, and `Tooltip` primitives.
- The waveform SVG remains generated by `renderSvg`. A React waveform-canvas component attaches the existing pointer behavior through explicit event handlers and commits only semantic operations.
- A browser bundle is emitted into `dist/assets`; the existing authenticated Worker continues to serve the bundle and the HTML entry point.

## Compatibility decisions

- Preserve schema version, browser-local storage key, document history shape, import/export formats, and existing Google authentication endpoints.
- Preserve the fixed signal-label rail, horizontal panning, complete PNG export, and fresh built-in example-copy semantics.
- Keep all SVG geometry and pointer interaction behavior as application code; Ant Design does not replace the waveform canvas.

## Test strategy

- Keep domain, renderer, import/export, authentication, and Worker tests unchanged.
- Add public React UI tests for the mounted editor shell, key authoring controls, invalid/repair state, history/example behavior, export state, and authenticated bundle availability.
- Exercise the final browser bundle through the existing Worker asset-graph test.

## Out of scope

- Theme finder assistant, new waveform semantics, collaboration, database persistence, additional authentication providers, and a data-model/schema migration.
